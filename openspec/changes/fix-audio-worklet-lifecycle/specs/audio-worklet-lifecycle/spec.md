# Lifecycle native AudioWorklet

## Purpose

Обеспечить освобождение принадлежащих SDK аудиоресурсов после остановки или неуспешного запуска эмулятора, чтобы повторное создание плеера не оставляло работающие контексты и обработчики предыдущего экземпляра.

## ADDED Requirements

### Requirement: Освобождение аудио при остановке

SDK MUST при остановке через `CommandInterface.exit()` инициировать закрытие принадлежащего экземпляру `AudioContext`, отключить его `AudioWorkletNode`, закрыть принадлежащий ему доступный `MessagePort` и удалить установленные для возобновления аудио обработчики жестов. После завершения асинхронного закрытия контекст SHALL находиться в состоянии `closed`. Это поведение MUST выполняться для direct и worker backend.

#### Scenario: Остановка работающего экземпляра
- **WHEN** успешно запущенный direct или worker backend с native worklet останавливается через `CommandInterface.exit()`
- **THEN** его контекст переходит в `closed`, узел отключён, аудиоканал освобождён, а прежние обработчики `pointerdown` и `keydown` удалены

#### Scenario: Остановка до первого пользовательского жеста
- **WHEN** экземпляр останавливается с контекстом в состоянии `suspended`
- **THEN** контекст также закрывается, и последующий пользовательский жест не возобновляет аудио остановленного экземпляра

### Requirement: Освобождение ресурсов при неуспешной инициализации

SDK MUST освобождать уже созданные аудиоресурсы при ошибках создания worklet и инициализации backend. Ошибка backend SHALL оставаться доступной вызывающему коду, а существующее поведение fallback при недоступном worklet MUST сохраняться.

#### Scenario: Ошибка загрузки worklet или создания узла
- **WHEN** после создания контекста завершается ошибкой загрузка модуля worklet или создание узла
- **THEN** созданный контекст закрывается, частично созданные ресурсы освобождаются, и SDK сохраняет прежний fallback без worklet

#### Scenario: Ошибка инициализации backend
- **WHEN** после создания аудио завершается ошибкой инициализация direct backend или обе попытки установки worker backend
- **THEN** аудиоресурсы освобождаются, и вызывающий код получает ошибку инициализации вместо успешного результата

### Requirement: Сообщения об ошибках не останавливают аудио

Само по себе сообщение `ws-err` в direct или worker backend либо событие `Worker.onerror` MUST NOT закрывать аудио, завершать transport или прерывать асинхронное создание backend. Существующий канал сообщений об ошибках MUST сохраняться. Очистка при фактическом завершении backend и отклонении инициализации SHALL сохраняться.

#### Scenario: Сообщение ws-err работающего backend
- **WHEN** работающий direct или worker backend сообщает `ws-err`
- **THEN** аудиоконтекст и узел остаются активными, порт и обработчики возобновления аудио сохраняются, а сообщение передаётся существующему обработчику

#### Scenario: Ошибка worker во время создания аудио
- **WHEN** ошибка worker возникает до завершения асинхронной загрузки worklet
- **THEN** сама ошибка не прерывает установку worker, созданные аудиоресурсы сохраняются до последующего завершения backend

#### Scenario: Ошибка работающего worker
- **WHEN** работающий worker с созданным аудио получает событие `Worker.onerror`
- **THEN** аудиоресурсы и transport сохраняются, а последующий `CommandInterface.exit()` дожидается `ws-exit` и освобождает аудио

### Requirement: Повторная очистка и повторный запуск безопасны

Освобождение аудиоресурсов MUST быть идемпотентным. Новый экземпляр MUST владеть собственными ресурсами независимо от ранее остановленных экземпляров.

#### Scenario: Повторное завершение
- **WHEN** очистка одного экземпляра вызывается повторно после нормальной остановки или ошибки
- **THEN** повторная очистка не выбрасывает исключений и не закрывает повторно контекст, порт или узел

#### Scenario: Цикл создания, остановки и повторного создания
- **WHEN** браузерный плеер с native worklet создан, остановлен, создан повторно и снова остановлен
- **THEN** после каждой остановки все контексты этого экземпляра закрыты, а во время второго запуска активен только контекст нового экземпляра

### Requirement: Совместимость и поставка исправления

SDK MUST сохранять публичные `CommandInterface`, `BackendOptions`, существующее включение native worklet и алгоритм обработки аудио. Исправление MUST входить в стандартный production-пакет SDK и не требовать изменения файлов зависимости или подстановки JavaScript на стороне потребителя.

#### Scenario: Использование стандартного пакета
- **WHEN** потребитель устанавливает выпущенную исправленную версию SDK и запускает DOSBox или DOSBox-X с native worklet
- **THEN** исправление lifecycle действует без применения patch-файлов, тестового override или отключения worklet в потребителе

#### Scenario: Проверка обратной совместимости
- **WHEN** запускаются существующие проверки протокола, аудио и backend без изменения клиентского кода
- **THEN** публичные сигнатуры и формат обмена сохраняются, а проверки проходят без изменения ожидаемого поведения DSP
